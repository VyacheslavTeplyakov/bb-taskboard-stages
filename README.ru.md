# Taskboard Stages

[English](README.md) · [История изменений](CHANGELOG.md) · [Разработка](CONTRIBUTING.md)

Канбан проектов внутри BB по меткам GitHub `stage:*`. Положение карточки
независимо от Open/Closed: закрытая задача может находиться в «Разработке»,
а открытая — в «Завершено».

Это форк [Taskboard](https://github.com/MateoCerquetella/bb-plugins) под лицензией MIT.
У каждого проекта свои названия и порядок колонок. Есть отдельная страница,
панель рядом с чатом, перенос мышью, меню этапа и команды для агента.
GitHub Projects и отдельный трекер не требуются.

## Установка

Нужны BB 0.47.1 или новее с совместимым SDK, GitHub CLI с действующей
авторизацией и проект BB с GitHub remote. Проверенная версия SDK — 0.6.79.
Для записи этапов нужны права на изменение меток issues.

```bash
bb plugin install git:https://github.com/VyacheslavTeplyakov/bb-taskboard-stages.git@v0.1.0
```

Для получения совместимых обновлений ветки 0.1 используйте `@^0.1.0`.
Идентификатор плагина — `taskboard-stages`, команда — `bb stageboard`.

Если используете форк вместо оригинала, отключите прежний плагин:

```bash
bb plugin disable taskboard
```

Отключение сохраняет его данные. Настройки и секреты оригинала автоматически
не переносятся; у форка отдельное хранилище. GitHub использует имеющийся вход `gh`.

## Настройка

Откройте Taskboard Stages, выберите проект и перейдите в Manage. Проверьте
подключённый GitHub-репозиторий. В «Этапы GitHub-канбана» задайте названия,
метки и порядок колонок, затем сохраните профиль. «Пример этапов» заполняет
редактируемый черновик.

Сохранение профиля не изменяет GitHub. «Проверить метки» читает их наличие;
отдельная кнопка создаёт отсутствующие метки, не меняя issues. Экспорт и импорт
переносят только профиль; импорт применяется после сохранения. Пустой профиль
возвращает стандартное представление Taskboard.

В режиме Kanban карточки группируются по этапу. Их можно переносить мышью или
выбирать этап через меню. Open/Closed показан и меняется отдельно. Issues без
метки попадают в «Без этапа», с неизвестными или несколькими метками — в
«Требует настройки». Явное назначение этапа исправляет неоднозначность.
Обычные метки сохраняются. Ошибки записи и время синхронизации видны на доске.

## Для агента

Используйте [навык stageboard](skills/stageboard/SKILL.md) с явным проектом:

```bash
bb stageboard stages list --project <project-id> --json
bb stageboard stages move 'owner/repo#42' stage:review --project <project-id> --json
```

Archivarius поддерживает актуальность доски; координатор проекта определяет
готовность и передачу работы. Чтение доски и смена этапа не запускают агентов.
Автономная фабрика по умолчанию выключена.

При конфликте, частичной записи или потерянном ответе перечитайте issue перед
повторной попыткой. В GitHub несколько операций над метками не являются общей
транзакцией. Прогресс CI, merge и завершение агента сами по себе этап не меняют.

## Разработка и происхождение

Из корня репозитория: `npm ci`, затем `npm run check`. Нужен установленный BB CLI.
Проверки включают типы, 345 тестов и сборку. Для сборки нужен Node.js 22.19+;
CI использует Node.js 26 и BB 0.47.1. Тесты не используют настоящие GitHub issues.

База: Taskboard 0.3.6, коммит `2dcad8a23bd06121b5c42faaf7ea0716f24b4915`.
История upstream, лицензия MIT и уведомления авторов сохранены. Основная ветка
форка — `taskboard-stages`; плагин находится в корне. Ветка upstream `main`
содержит исходный монорепозиторий. Порядок обновления описан в CONTRIBUTING.md.
